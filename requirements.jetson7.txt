# =============================================================================
# requirements.jetson7.txt — Jetson Orin Nano / JetPack 7.2 container deps
#
# Companion to Dockerfile.jetson (Ubuntu 24.04, Python 3.12, CUDA 13,
# TensorRT 10.16). Do NOT use this on bare-metal JetPack 6 — that is
# requirements.jetson.txt — and do NOT use the x86 requirements.txt on Jetson.
#
# Like requirements.jetson.txt, this is a flat, fully enumerated dependency
# set that MUST be installed with --no-deps: several packages below declare
# opencv-python (which would replace Ubuntu's GStreamer-enabled cv2) or
# torch/numpy (which would replace the CUDA wheels / the numpy 1.26 that
# Ubuntu's cv2 ABI requires). Dockerfile.jetson runs:
#
#   pip install --no-deps --no-build-isolation -r requirements.jetson7.txt
#   pip install --no-deps ultralytics==8.4.45
#   pip install --no-deps --no-build-isolation \
#       git+https://github.com/KaiyangZhou/deep-person-reid.git@f8cd150fdf77e8d9e1ed143b7f308c2c609ded50
#
# Deliberately MISSING (provided elsewhere):
#   torch, torchvision   -> installed from download.pytorch.org/whl/cu130
#                           (2.9.1+cu130 / 0.24.1+cu130, aarch64 wheels)
#   tensorrt             -> apt python3-libnvinfer=10.16.1.11-1+cuda13.2,
#                           visible through the --system-site-packages venv
#   opencv, numpy        -> apt python3-opencv 4.6.0 (GStreamer+FFmpeg build)
#                           and its matching python3-numpy 1.26; pinning numpy
#                           here would break the cv2 ABI (numpy 2 is not
#                           binary-compatible with modules built against 1.x)
#   torch_tensorrt       -> intentionally absent; aarch64 uses the raw
#                           ONNX->TensorRT backend (SIAMRAM_TRT_BACKEND=raw)
#   albumentations       -> training-only, drags in opencv-python-headless
#   pynvvideocodec       -> dGPU-only; Jetson NVDEC goes through GStreamer
#
# Changes vs requirements.jetson.txt (JetPack 6 / Python 3.10):
#   onnx 1.17.0 -> 1.18.0   torch 2.9.1's CI-tested onnx, and exactly the
#                           release the TensorRT 10.16 ONNX parser supports
#                           (onnx-tensorrt release/10.16-GA). The tracker
#                           exports at opset 17, well inside both ranges.
#   setuptools<60 dropped   that pin was a py3.10/numpy.distutils workaround
#                           and does not support Python 3.12.
#   pillow/scipy/pandas/... added below: on JetPack 6 these came from the
#                           l4t-ml base image; this container must carry them.
# =============================================================================
